## 将 dev 的 EMI 配置 commit 回移（backport）到 0.8.8

- 源 commit：`c86fc9b` "add 'EMI' compat configs for every supported MC version"（dev）
- 目标分支：`0.8.8`（当时 HEAD 19ef5b3），本地提交 `aef5d28`，未 push
- 做法：
  - `git cherry-pick -n` 在 3 个 `manifest.json` 上冲突；因不需要 manifest 变更，改用
    `git checkout c86fc9b -- <7 个 mods/emi.json>` 只取文件
  - 用仓库脚本 `python3 generate_manifest.py` 在本分支本地重新生成 manifest
    （脚本只在内容变化时重写，其余 category 保持不动），而不是照抄 dev 的 manifest
  - 提交时保留原作者与 author date（`--author` + `GIT_AUTHOR_DATE`），并加
    `(cherry picked from commit ...)` trailer
- 结果：14 个文件 —— 7 个 `emi.json`（1.18.2/fabric、1.19.2/fabric、1.19.2/forge、
  1.20.1/fabric、1.20.1/forge、1.21.1/fabric、1.21.1/neoforge）+ 3 个新建 manifest +
  4 个重新生成的 manifest；emi.json 与源 commit 逐字节一致

## 经验（重要）

- `manifest.json` 中记录每个配置的 `sha256`，**只加 `mods/*.json` 而不更新 manifest，
  客户端根本索引不到该配置**。新增/修改配置后必须跑 `generate_manifest.py`。
- `git cherry-pick -n` 发生冲突后若报 "no cherry-pick or revert in progress"，
  说明 `-n` 未写入 CHERRY_PICK_HEAD，直接 `git reset --hard HEAD` 回到干净状态即可。
- 分支版本范围不一致：release 分支（0.8.7/0.8.8/0.8.9/main）只有 1.20.1 及以上；
  `1.12.2 / 1.16.5 / 1.18.2 / 1.19.2` 仅存在于 `dev`。跨分支 backport 需确认是否要新建版本目录。
