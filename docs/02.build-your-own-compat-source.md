# Build Your Own Compat Source

> Applies to **ControlFlex ≥ 0.8.7** (the "Edit source list / Sync latest configs" features of the Mod Adaptation page).
> For the config JSON field reference see [01.config-field-reference](./01.config-field-reference.md); this document covers the *source* publishing layer only.

A mod compat **source** is a **purely static HTTP directory tree**: ControlFlex fetches a `manifest.json` plus per-mod config JSON files from it using fixed URL rules. Once a player adds your baseUrl to their source list in-game, they can browse, preview, and one-click-apply the adaptation configs you publish.

ControlFlex's built-in official source is this very repository (`cfx-compat-configs`), so **publishing your own source = hosting a set of static JSON files that follow the layout below** — no server-side logic required.

---

## 1. How the client consumes a source

In-game entry point: **ControlFlex Settings → Mod Adaptation → top-right "More" menu → "Edit source list" / "Sync latest configs"**.

For each source, ControlFlex requests exactly two kinds of URLs:

```text
Manifest: {baseUrl}/{mcVersion}/{loader}/manifest.json
Content:  {baseUrl}/{mcVersion}/{loader}/{path}      # path from a manifest item, e.g. mods/jei.json
```

- `{mcVersion}`: the running game's version name (`SharedConstants.getCurrentVersion().getName()`, e.g. `1.20.1`) — **exact directory-name match**, no fuzzy or fallback matching.
- `{loader}`: the current loader name (`forge` / `fabric` / `neoforge`). **Only the current loader's directory is fetched** — a fabric instance never reads the forge directory.
- A missing `{mcVersion}/{loader}` directory on your source (404) is **normal**: it logs "this source has no manifest for the current version" as info, does not count as a failure, and other sources are unaffected. Serving configs for only some MC versions/loaders is fine.

Hard limits:

| Item | Limit |
|------|-------|
| baseUrl scheme | Must be `http://` or `https://` with a host name |
| Per-file size | **≤ 2 MB** (applies to manifests and content files; oversized files are dropped) |
| Timeouts | 5 s connect / 30 s read |
| Redirects | 301/302/303/307/308 followed, max 5 hops; **https→http downgrade rejected** |
| Encoding | UTF-8 JSON |

## 2. Quick start: fork this repository in six steps

The fastest path is not building the tree from scratch — **fork this repository**: the layout, the manifest generator, and a set of working configs are already in place. Just add your own configs and push:

1. **Fork this repository** (the Fork button on GitHub).
   ⚠ Mind the branch: config formats differ between ControlFlex versions, and sources are consumed **per branch** — develop on the branch matching your ControlFlex version (e.g. `0.8.7`). If your fork only copied the default branch `main` (legacy format), check out `0.8.7` from upstream into your fork first.
2. **Edit / add configs**: create or modify `<mc-version>/<loader>/mods/<mod_id>.json` (field reference: [01.config-field-reference](./01.config-field-reference.md)); copy the same file into every loader directory it should cover.
3. **Regenerate manifests and push**:
   ```bash
   python3 generate_manifest.py   # required: refresh the sha256 values in manifest.json
   git add -A && git commit -m "add <modid> config" && git push
   ```
   Editing configs without re-running the script is the #1 cause of "content download failed" on the player side (see §10).
4. **Get your source URL** (replace `<user>` with your GitHub username):
   ```text
   https://raw.githubusercontent.com/<user>/cfx-compat-configs/refs/heads/0.8.7   # recommended: visible ~5 min after push
   https://cdn.jsdelivr.net/gh/<user>/cfx-compat-configs@0.8.7                    # faster CDN, but @branch cached ~12 h
   ```
   Verify in a browser that `<source-url>/1.20.1/forge/manifest.json` opens. The repository must be **public** — private repos require authentication on raw URLs and cannot serve as a source.
5. **Add the source in ControlFlex settings and sync**: Settings → Mod Adaptation → top-right "More" menu → "Edit source list" → paste the URL into the input at the bottom → Add → Done; then open "Sync latest configs" and confirm your source synced successfully (per-source progress and logs).
6. **Preview and apply**: open the mod's detail page — the banner shows "N community adaptation configs found" → pick a variant → read-only preview → "Apply", effective **immediately, no restart needed**. When your fork serves the same `mod_id` with different content (different sha256) than the official source, it shows up as a **parallel variant** in the variant list for the player to choose from.

> **Day-to-day iteration**: edit configs → `python3 generate_manifest.py` → push → hit "Sync latest configs" in-game once more. The raw URL reflects changes in ~5 minutes; jsDelivr waits out its cache (or publish a fixed tag instead).
> **Follow upstream**: when this repository updates, use GitHub's "Sync fork" on your fork, then re-run the generator.
> **Don't want a public repo?** Use local testing (§9) or self-hosted hosting (§6) instead; private GitHub repositories cannot serve as a source directly.

## 3. Repository layout

```text
<repo-root>/                       # the URL of this root is the baseUrl players enter
├── 1.20.1/                        # MC version directory (must match the game's version name)
│   ├── forge/
│   │   ├── manifest.json          # manifest of compat configs for this version+loader
│   │   └── mods/
│   │       ├── jei.json
│   │       └── epicfight.json
│   └── fabric/
│       ├── manifest.json
│       └── mods/
│           └── jei.json
├── 1.21.1/
│   ├── neoforge/
│   └── fabric/
└── ...
```

Notes:

- **For MC versions/loaders you don't cover, just don't create the directory** — the client treats it as 404 and skips safely.
- If a config behaves identically across loaders, copy the same file into each loader directory; if it targets a specific loader only, put it just in that loader's directory (loader separation is decided entirely by the directory layout — there is no loader field inside the config file).
- Name files under `mods/` after their `mod_id` (`<mod_id>.json`) for maintainability. Identity is determined by the JSON's `mod_id` field, not the filename — but Apply always writes the user file as `user/<mod_id>.json`.

## 4. manifest.json specification

```json
{
  "schemaVersion": 1,
  "name": "ControlFlex Community Configs",
  "generated": "2026-08-29T01:03:58Z",
  "items": [
    {
      "mod_id": "jei",
      "mod_name": "Just Enough Items (JEI)",
      "path": "mods/jei.json",
      "sha256": "a4dcfadbca3d0a8b19be2ec5d191fc12801d199583393ef0fec13007e06b927f",
      "home_pages": [
        { "name": "CurseForge", "url": "https://www.curseforge.com/minecraft/mc-mods/jei", "description": "Project homepage" },
        "https://modrinth.com/mod/jei"
      ],
      "description": "JEI gamepad adaptation",
      "dependencies": [
        { "mod_id": "cfx-jei-extra", "mod_name": "JEI Extra", "home_pages": ["https://..."], "description": "Optional" }
      ]
    }
  ]
}
```

| Field | Req. | Validation (violations fail the **whole manifest sync**) |
|------|:----:|------|
| `schemaVersion` | No | Number. **Rejected when greater than `1`** (client shows an upgrade hint); missing or `0` tolerated. |
| `name` | No | Display name of the source. |
| `generated` | No | Manifest generation time, display only. |
| `items` | No* | Must be an array (present but not an array → failure). |
| `items[].mod_id` | Yes | Must match `^[a-z0-9_-]+$`; **must be unique within the manifest** — a duplicate mod_id fails the entire manifest parse. |
| `items[].mod_name` | No | Display name; falls back to mod_id. |
| `items[].path` | Yes | **Relative to the manifest's directory**: no absolute paths, no backslashes, no empty/`.`/`..` segments; convention `mods/<file>.json`. Used only to build download URLs. |
| `items[].sha256` | Yes | SHA-256 of the content file, 64 lowercase hex chars. Verified after download; mismatch → try the next mirror URL. **The sole identity of a variant.** |
| `items[].home_pages` | No | Array of plain URL strings and/or `{name, url, description}` objects, mixed allowed; non-http(s) entries silently dropped. |
| `items[].description` | No | One-line summary, display only. |
| `items[].dependencies` | No | Display-only metadata `{mod_id, mod_name, home_pages, description}`; the client **never** installs dependencies. Entries with invalid mod_id are skipped. |

> `*`: an empty `items` list is valid (no configs for this version/loader yet).
>
> Note: `description` / `dependencies` are currently **not generated** by this repo's `generate_manifest.py` (re-running the script drops hand-added copies of these fields). Either live without summaries or extend the script / maintain them by hand.

Content files (`mods/*.json`) must parse as a `ModCompatConfig` (valid JSON, a `mod_id`, `mod_versions` array, etc.) or preview/apply fails. Note: the content file's `mod_id` must point at an installed mod, and its `dependencies[].mod_id` acts as an **activation gate** (all must be loaded to take effect). Field reference: [01.config-field-reference](./01.config-field-reference.md).

## 5. Generating the manifest

Reuse this repo's generator (idempotent: leaves `manifest.json` untouched when content is unchanged):

```bash
# Put a copy of generate_manifest.py at the root of your source repo
python3 generate_manifest.py
```

What it does: scans every `<mc-version>/<loader>/mods/*.json` → extracts `mod_id` / `mod_name` / `home_pages` (a top-level `home_page` URL string is auto-wrapped into a list) → computes the byte-level SHA-256 → atomically writes `manifest.json` per the spec. Invalid `mod_id`, broken JSON, duplicate mod_id etc. produce warnings and skip the offending file.

Manual maintenance also works: `sha256sum mods/*.json` and fill in the hashes — but **you must regenerate after every content edit**, otherwise the client downloads the content, the hash check fails, and the whole round is abandoned.

## 6. Choosing a host

A source only needs static file hosting:

| Option | baseUrl example | Caching | Notes |
|--------|-----------------|---------|-------|
| GitHub + jsDelivr | `https://cdn.jsdelivr.net/gh/<user>/<repo>@<branch>` | `@branch` refs cached ~**12 h** | Fast global CDN; updates lag behind until cache expires — prefer release tags (`@v1.0.0`) |
| GitHub raw | `https://raw.githubusercontent.com/<user>/<repo>/refs/heads/<branch>` | ~5 min | Updates visible quickly; the official built-in source uses this form |
| Self-hosted / object storage | `https://files.example.com/cfx-source/` | Up to you | Any HTTP service that serves static files by path works |

> The official built-ins mirror each other: the same sha256 present in multiple sources is tried **in source-list order**, first success wins — this also absorbs CDN-vs-raw cache inconsistency.

The official built-in sources (from ControlFlex 0.8.7, pinned per release to the matching branch of this repo):

```text
https://cdn.jsdelivr.net/gh/ControlFlexMC/cfx-compat-configs@0.8.7
https://raw.githubusercontent.com/ControlFlexMC/cfx-compat-configs/refs/heads/0.8.7
```

## 7. From scratch: full publishing walkthrough

> This is the full **build-your-own-tree-from-scratch** path; if you just want to add a few configs on top of the official repository, follow the fork quick start in §2 instead.

1. **Create a Git repository** (or a static site directory), place your configs per §3: `<mc-version>/<loader>/mods/<mod_id>.json`.
2. **Run `generate_manifest.py`** to produce each directory's `manifest.json`; make sure there are no warnings.
3. **Commit and push**.
4. **Determine the baseUrl** (§6) and verify both URLs open in a browser:
   - `{baseUrl}/{your-mc-version}/{loader}/manifest.json`
   - `{baseUrl}/{your-mc-version}/{loader}/mods/<mod_id>.json`
5. **Add the source in-game**: Settings → Mod Adaptation → "More" → "Edit source list" → paste the baseUrl into the input at the bottom → Add → Done. Closing the dialog triggers a background sync when the list changed.
6. Open "Sync latest configs" and confirm your source synced successfully (per-source progress and logs). The mod's card then shows a community-configs badge and its detail page shows the "N community adaptation configs found" banner.
7. Click the banner → pick a variant → **read-only preview** → "Apply". Apply takes effect **immediately, no restart needed**.

Source-list behavior: built-in sources can be disabled/reordered but not deleted; your sources can be added/removed/reordered freely; "Restore default sources" only resets the two built-ins and never deletes yours. Each source caches under `repo/manifest/<source-id>/` (id derived from the URL, lowercase; conflicts get `-1`/`-2` suffixes).

## 8. Sync → Apply lifecycle (player's perspective)

Understanding this helps you plan updates:

- **Sync** only refreshes manifests; it runs silently after startup and can be triggered manually. After the manifest stage the client **pre-downloads all missing content variants** into the local content cache (content-addressed: `config/controlflex/compat/repo/content/<mod_id>/<sha256>.json`, files immutable).
- **Same mod_id + different sha256 = parallel variants** the player chooses from; **same sha256 in multiple sources = mirrors** with source-order failover.
- **Apply**: backs up the player's existing config to `config/controlflex/compat/backup/<mod_id>-<timestamp>.json` → atomically overwrites `user/<mod_id>.json` → records it in `user/.applied.json` → hot-reloads that mod's config.
- **Undo**: "Reset config" on the detail page, or manually delete `user/<mod_id>.json` → falls back to the built-in default layer.
- If the player edited an applied file by hand, the variant list shows "Modified by user"; applying again creates a fresh timestamped backup.
- A config only actually activates if its own gates pass: the target mod (`mod_id`) is loaded, every `dependencies[].mod_id` is loaded, and a `mod_versions` entry matches — unsatisfied conditions simply mean inactive.

**Updating an adaptation**: edit `mods/*.json` → regenerate the manifest → push. On the player's next sync the manifest refreshes and the new sha256 downloads as a new variant; players who applied the old version and modified it need to re-apply (an automatic backup is made).

## 9. Local testing

Fastest path — serve your repo locally and add it as a source:

```bash
cd <your-source-repo-root>
python3 -m http.server 8000
# In-game "Edit source list", add: http://127.0.0.1:8000
```

`http://` sources are allowed (only https→http redirect downgrades are rejected), so no certificates are needed for local testing. Edit files, hit "Sync latest configs", and see the result.

> Developer test hook: the system property `controlflex.repo.officialBaseUrl` can redirect the built-in official sources (testing only, never set in production).

## 10. Troubleshooting checklist

| Symptom | Check |
|---------|-------|
| Source shows "Never synced" / sync failed | 1) Open `{baseUrl}/{mcVersion}/{loader}/manifest.json` in a browser; 2) directory names must **exactly** match the game version name / loader name (`1.20.1`, not `1.20`); 3) files ≤ 2 MB; 4) no https→http redirect downgrade |
| Log: manifest parse error | Common causes: duplicate `mod_id` in `items`; `path` with absolute path/backslash/`..`; `sha256` not 64 lowercase hex; `schemaVersion` > 1; JSON syntax errors |
| Manifest synced but content download fails | Content bytes don't match the manifest `sha256` (**edited the JSON but forgot to regenerate the manifest** is the #1 cause), over 2 MB, or all mirrors failed in the round |
| Applied but nothing changed | The config's own gates failed: the `mod_id` mod not installed, `dependencies` not fully loaded, no `mod_versions` entry matches the installed mod version (first match wins — mind interval syntax and order), wrong key names. Search logs for `[ModCompat]` |
| Players don't see your update | jsDelivr `@branch` caches ~12 h; switch to the raw URL, cut a tag, or wait for expiry |
| Garbled non-ASCII text | Files must be UTF-8 (no BOM preferred) |

---

## 11. Publishing quality checklist

- `mod_id` is a required field (missing/empty → the whole file is skipped); use semantic `config_version` so players can recognize updates.
- Provide `en_us` in `tips` at minimum, ideally plus other common languages; runtime looks up the player's language and falls back to `en_us`.
- Test on every MC version/loader you publish for before release; configs PR'd to this repo are reviewed before merge.
- Keep every file ≤ 2 MB (in practice compat configs are only a few KB).
- You're always welcome to contribute configs directly to this repository (see the [README contribution flow](../README.md)); a self-hosted source fits experimental configs, private modpack customization, or authors who want an independent release cadence.
