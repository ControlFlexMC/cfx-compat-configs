# 如何构建自己的模组适配源

> 适用版本：**ControlFlex ≥ 0.8.7**（模组适配页的「编辑源列表 / 同步最新配置」功能）。
> 配置 JSON 本身的字段规范见 [01.config-field-reference](./01.config-field-reference_ZH.md)，本文只讲"源"这一层的发布规则。

「模组适配源」（下称**源**，source）是一个**纯静态的 HTTP 目录树**：ControlFlex 按固定规则从中拉取 `manifest.json` 与各模组的适配配置 JSON，玩家在游戏内把你的 baseUrl 加入源列表后，即可浏览、预览并一键应用你发布的适配方案。

ControlFlex 内置的官方源就是本仓库（`cfx-compat-configs`），所以**发布一个自己的源 = 按下面的目录与文件规范托管一批静态 JSON 文件**，不需要任何服务端逻辑。

---

## 1. 客户端如何消费一个源

游戏内入口：**ControlFlex 设置 → 模组适配 → 右上角「更多」→「编辑源列表 / 同步最新配置」**。

对一个源，ControlFlex 只会请求两类 URL：

```text
清单：{baseUrl}/{mcVersion}/{loader}/manifest.json
内容：{baseUrl}/{mcVersion}/{loader}/{path}      # path 来自清单条目，如 mods/jei.json
```

- `{mcVersion}`：游戏当前版本名（`SharedConstants.getCurrentVersion().getName()`，如 `1.20.1`），**精确匹配目录名**，没有模糊/回退匹配。
- `{loader}`：当前加载器名（`forge` / `fabric` / `neoforge`）。**只拉取当前加载器目录**，一个 fabric 实例不会去读 forge 目录。
- 源上不存在当前 `{mcVersion}/{loader}` 目录（404）是**正常情况**：日志记为"该源没有当前版本的清单"，不算失败，其他源不受影响。所以只为部分 MC 版本/加载器提供配置是允许的。

硬性限制：

| 项目 | 限制 |
|------|------|
| baseUrl 协议 | 必须是 `http://` 或 `https://` 且有主机名 |
| 单文件大小 | **≤ 2 MB**（清单和内容文件都受限，超限直接丢弃该文件） |
| 超时 | 连接 5 秒 / 读取 30 秒 |
| 重定向 | 跟随 301/302/303/307/308，最多 5 跳；**拒绝 https→http 降级** |
| 编码 | UTF-8 JSON |

## 2. 快速上手：Fork 本仓库，六步建好自己的源

最快的路径不是从零搭目录，而是**直接 Fork 本仓库**——目录布局、清单生成脚本、现成配置都是对的，你只需加上/改出自己的配置再推送：

1. **Fork 本仓库**（GitHub 右上角 Fork）。
   ⚠ 注意分支：不同 ControlFlex 版本的配置格式不同，源是**按分支**消费的，请基于与你的 ControlFlex 版本对应的分支开发（如 `0.8.7`）。若 Fork 时只复制了默认分支 `main`（旧格式），先从上游检出 `0.8.7` 分支到你的 Fork。
2. **修改 / 添加配置**：新建或修改 `<MC版本>/<加载器>/mods/<mod_id>.json`（字段规范见 [01.config-field-reference](./01.config-field-reference_ZH.md)）；需要覆盖多个加载器就把同一文件复制到各加载器目录。
3. **重新生成清单并推送**：
   ```bash
   python3 generate_manifest.py   # 必做：更新 manifest.json 中的 sha256
   git add -A && git commit -m "add <modid> config" && git push
   ```
   改了配置却忘了重跑脚本，是玩家端"内容下载校验失败"的头号原因（见 §10 排错清单）。
4. **得到你的源地址**（把 `<user>` 换成你的 GitHub 用户名）：
   ```text
   https://raw.githubusercontent.com/<user>/cfx-compat-configs/refs/heads/0.8.7   # 推荐：推送后约 5 分钟生效
   https://cdn.jsdelivr.net/gh/<user>/cfx-compat-configs@0.8.7                    # CDN 更快，但 @分支 缓存约 12 小时
   ```
   先在浏览器里验证 `<源地址>/1.20.1/forge/manifest.json` 能直接打开。注意仓库必须是**公开**的（私有仓库的 raw 链接需要鉴权，无法作为源）。
5. **在 ControlFlex 设置中添加源并同步**：设置 → 模组适配 → 右上角「更多」→「编辑源列表」→ 底部粘贴源地址 → 添加 → 完成；再打开「同步最新配置」确认你的源同步成功（进度与日志逐源展示）。
6. **预览并应用**：进入对应模组的详情页，顶部横幅显示「发现 N 个社区适配方案」→ 选择变体 → 只读预览 → 「应用」，**立即生效，无需重启**。你的 Fork 与官方源提供同 `mod_id` 但内容不同（sha256 不同）的配置时，会作为**并列变体**一起出现在变体列表里，玩家自选。

> **日常迭代**：改配置 → `python3 generate_manifest.py` → push → 游戏内再点一次「同步最新配置」。raw 地址约 5 分钟内生效；jsDelivr 需等缓存过期（或改用固定 tag 发布）。
> **跟进上游**：本仓库更新时，用 GitHub Fork 页面的「Sync fork」同步上游，再重跑生成脚本。
> **不想公开仓库？** 改走本地测试（§9）或自建托管（§6）；私有 GitHub 仓库无法直接作为源。

## 3. 目录布局

```text
<repo-root>/                       # 这个根目录的 URL 就是玩家填写的 baseUrl
├── 1.20.1/                        # MC 版本目录（与 SharedConstants 版本名一致）
│   ├── forge/
│   │   ├── manifest.json          # 该版本+加载器下的适配配置清单
│   │   └── mods/
│   │       ├── jei.json
│   │       └── epicfight.json
│   └── fabric/
│       ├── manifest.json
│       └── mods/
│           └── jei.json
├── 1.21.1/
│   ├── neoforge/
│   └── fabric/
└── ...
```

要点：

- **未覆盖的 MC 版本/加载器直接不建目录即可**，客户端视为 404，安全跳过。
- 同一份配置内容如果各加载器行为一致，就把同一文件复制到各加载器目录；某个配置只适用于特定加载器时，只放进对应加载器的目录即可（加载器的区分完全由目录结构决定，配置文件内没有加载器字段）。
- `mods/` 下文件名建议与 `mod_id` 一致（`<mod_id>.json`），便于维护；客户端识别身份依据的是 JSON 里的 `mod_id` 字段而非文件名，但「应用」落盘时用户文件固定叫 `user/<mod_id>.json`。

## 4. manifest.json 规范

```json
{
  "schemaVersion": 1,
  "name": "ControlFlex Community Configs",
  "generated": "2026-08-29T01:03:58Z",
  "items": [
    {
      "mod_id": "jei",
      "mod_name": "Just Enough Items (JEI)",
      "path": "mods/jei.json",
      "sha256": "a4dcfadbca3d0a8b19be2ec5d191fc12801d199583393ef0fec13007e06b927f",
      "home_pages": [
        { "name": "CurseForge", "url": "https://www.curseforge.com/minecraft/mc-mods/jei", "description": "项目主页" },
        "https://modrinth.com/mod/jei"
      ],
      "description": "JEI 手柄适配",
      "dependencies": [
        { "mod_id": "cfx-jei-extra", "mod_name": "JEI Extra", "home_pages": ["https://..."], "description": "可选" }
      ]
    }
  ]
}
```

| 字段 | 必填 | 校验规则（不符会导致**整个清单同步失败**） |
|------|:----:|------|
| `schemaVersion` | 否 | 数字。**大于 `1` 时拒绝解析**（提示客户端需升级）；缺失或 `0` 可容忍。 |
| `name` | 否 | 源显示名。 |
| `generated` | 否 | 清单生成时间，仅展示。 |
| `items` | 否* | 必须是数组（存在但不是数组 → 失败）。 |
| `items[].mod_id` | 是 | 必须匹配 `^[a-z0-9_-]+$`；**清单内必须唯一**，重复 mod_id 会导致整个清单解析失败。 |
| `items[].mod_name` | 否 | 展示名，缺省回退为 mod_id。 |
| `items[].path` | 是 | **相对清单所在目录的相对路径**：不允许绝对路径、反斜杠、空段、`.`、`..`；约定 `mods/<文件名>.json`。仅用于拼接下载 URL。 |
| `items[].sha256` | 是 | 内容文件的 SHA-256，64 位小写十六进制。下载后逐字校验，不符即换下一个镜像 URL。**是变体身份的唯一标识**。 |
| `items[].home_pages` | 否 | 数组，元素可为纯 URL 字符串或 `{name, url, description}` 对象，可混用；非 http(s) 的条目被静默丢弃。 |
| `items[].description` | 否 | 一行简介，展示用。 |
| `items[].dependencies` | 否 | 展示用元数据 `{mod_id, mod_name, home_pages, description}`；客户端**不会**安装依赖。非法 mod_id 的条目被跳过。 |

> `*`：`items` 为空清单是合法的（该版本/加载器暂无配置）。
>
> 注意：`description` / `dependencies` 目前**不在**本仓库 `generate_manifest.py` 的生成范围内（脚本重新生成清单时会丢弃手工加的这两个字段）。要么接受没有简介，要么自行扩展脚本/手工维护。

内容文件（`mods/*.json`）必须能被 `ModCompatConfig` 解析（合法 JSON、有 `mod_id`、`mod_versions` 是数组等），否则应用/预览阶段失败。注意：内容文件的 `mod_id` 必须指向已安装的模组，且其 `dependencies[].mod_id` 是**激活门控**（全部已加载才生效）。字段规范见 [01.config-field-reference](./01.config-field-reference_ZH.md)。

## 5. 生成 manifest

推荐直接复用本仓库的生成脚本（幂等：内容没变就不会改写 `manifest.json`）：

```bash
# 在你的源仓库根目录放一份 generate_manifest.py（可直接复制本仓库的）
python3 generate_manifest.py
```

脚本行为：扫描所有 `<mc版本>/<loader>/mods/*.json` → 取 `mod_id` / `mod_name` / `home_pages`（兼容顶层 `home_page` 字符串，自动包装成列表）→ 计算文件字节级 SHA-256 → 按规范原子写出 `manifest.json`；`mod_id` 非法、JSON 损坏、重复 mod_id 等会以 warning 提示并跳过对应文件。

手动维护也可以：`sha256sum mods/*.json` 后把哈希填进清单，但**每次改动内容文件后必须同步更新清单**，否则客户端下载内容后校验失败、整轮放弃。

## 6. 托管方式选择

源只需要静态文件服务，常见选择：

| 方式 | baseUrl 示例 | 缓存行为 | 备注 |
|------|-------------|----------|------|
| GitHub + jsDelivr | `https://cdn.jsdelivr.net/gh/<user>/<repo>@<branch>` | `@分支` 引用缓存约 **12 小时** | 全球 CDN 快；更新后要等缓存过期，建议固定发版 tag（`@v1.0.0`） |
| GitHub raw | `https://raw.githubusercontent.com/<user>/<repo>/refs/heads/<branch>` | 约 5 分钟 | 更新可见快，官方内置源之一就是这种形态 |
| 自建 / 对象存储 | `https://files.example.com/cfx-source/` | 取决于你的服务 | 任意能按路径吐静态文件的 HTTP 服务均可 |

> 官方内置源把两者互为镜像：同一个 sha256 在多个源出现时，客户端按**源列表顺序**逐个尝试下载，任一成功即可，并天然吸收了 CDN 与 raw 缓存不一致的问题。

ControlFlex 内置的官方源（0.8.7 起，随版本固定到本仓库对应分支）：

```text
https://cdn.jsdelivr.net/gh/ControlFlexMC/cfx-compat-configs@0.8.7
https://raw.githubusercontent.com/ControlFlexMC/cfx-compat-configs/refs/heads/0.8.7
```

## 7. 从零自建：完整发布步骤

> 这是**从零搭建自己目录**的完整路径；如果只是想在官方仓库基础上加几个配置，直接看 §2 的 Fork 六步即可。

1. **建一个 Git 仓库**（或静态站点目录），按 §3 布局放入你写好的配置：`<mc版本>/<loader>/mods/<mod_id>.json`。
2. **运行 `generate_manifest.py`** 生成各目录的 `manifest.json`，确认无 warning。
3. **提交并推送**。
4. **确定 baseUrl**（§6），并在浏览器里手动验证这两个 URL 能打开：
   - `{baseUrl}/{你的MC版本}/{loader}/manifest.json`
   - `{baseUrl}/{你的MC版本}/{loader}/mods/<mod_id>.json`
5. **游戏内添加源**：设置 → 模组适配 → 「更多」→「编辑源列表」→ 底部输入框粘贴 baseUrl → 添加 → 完成。关闭对话框后若源列表有变化会自动触发一次后台同步。
6. 打开「同步最新配置」确认你的源同步成功（进度与日志逐源展示）；随后对应模组卡片出现社区配置角标、详情页顶部出现「发现 N 个社区适配方案」横幅。
7. 点进横幅 → 选择变体 → **只读预览** → 「应用」。应用成功**立即生效，无需重启**。

源列表行为：内置源可禁用/排序但不可删除；你的源可增删改排序；「恢复默认源」只重置内置两个源，不删你的源。每个源在磁盘上按 ID 派生规则缓存到 `repo/manifest/<source-id>/`，冲突时追加 `-1`/`-2` 后缀。

## 8. 同步 → 应用 的生命周期（玩家侧视角）

理解这套机制有助于你安排更新节奏：

- **同步**只刷新清单；启动后自动静默同步一次，也可手动触发。清单阶段之后，客户端会把**当前缺失的内容变体预下载**到本地内容缓存（内容寻址存储：`config/controlflex/compat/repo/content/<mod_id>/<sha256>.json`，文件不可变）。
- **同一个 mod_id、不同 sha256 = 并存的多变体**，玩家在变体列表里自选；**相同 sha256 出现在多个源 = 镜像**，按源顺序故障转移。
- **应用**：备份玩家现有配置到 `config/controlflex/compat/backup/<mod_id>-<时间戳>.json` → 原子覆盖 `user/<mod_id>.json` → 记录到 `user/.applied.json` → 热重载该模组配置。
- **撤销**：详情页「重置配置」，或手动删除 `user/<mod_id>.json` → 回落到内置 default 层。
- 玩家手动改过已应用的文件后，变体列表会显示「已被用户修改」，再应用一次会生成新的时间戳备份。
- 配置真正的激活还受配置自身的门控：目标模组（`mod_id`）已加载、`dependencies[].mod_id` 全部已加载、`mod_versions` 有条目命中 —— 条件不满足时自然不生效。

**更新你的适配方案**：改动 `mods/*.json` → 重新生成 manifest → push。玩家下次同步时清单更新、新 sha256 下载为新变体；已应用旧版并被改过的玩家需要重新应用（会自动备份）。

## 9. 本地测试

最快路径 —— 本机起一个静态服务器，把它当源加进游戏：

```bash
cd <你的源仓库根目录>
python3 -m http.server 8000
# 游戏内「编辑源列表」添加：http://127.0.0.1:8000
```

`http://` 源是允许的（只拒绝 https→http 的重定向降级），所以本地调试无需证书。改文件后手动「同步最新配置」即可看到效果。

> 开发者测试钩子：系统属性 `controlflex.repo.officialBaseUrl` 可重定向内置官方源（仅测试用，勿在生产设置）。

## 10. 排错清单

| 现象 | 排查 |
|------|------|
| 源显示「从未同步」/ 同步失败 | 1) 浏览器直接打开 `{baseUrl}/{mcVersion}/{loader}/manifest.json` 验证；2) 目录名是否与游戏版本名/加载器名**完全一致**（`1.20.1` 而非 `1.20`）；3) 文件是否 ≤ 2 MB；4) https 源是否被重定向降级到 http |
| 日志：manifest parse error | 常见原因：`items` 里 `mod_id` 重复；`path` 带绝对路径/反斜杠/`..`；`sha256` 不是 64 位小写 hex；`schemaVersion` > 1；JSON 语法错误 |
| 清单同步成功但内容下载失败 | 内容文件字节与清单 `sha256` 不符（**改了 JSON 忘了重新生成 manifest** 是头号原因）、超 2 MB、所有镜像同轮失败 |
| 应用成功但没有效果 | 配置自身门控未过：`mod_id` 模组未装、`dependencies` 依赖未装齐、`mod_versions` 没有条目匹配当前模组版本（首条匹配生效，注意区间写法与顺序）、按键名写错。开日志搜 `[ModCompat]` 看加载/警告行 |
| 玩家看不到最新改动 | jsDelivr `@分支` 缓存约 12 小时；换 raw 地址、打 tag，或等缓存过期 |
| 中文注释/字段乱码 | 文件必须 UTF-8（无 BOM 更佳） |

## 11. 发布质量建议

- `mod_id` 是必填字段（缺失或为空，整个文件会被跳过）；`config_version` 用语义版本，方便玩家识别更新。
- `tips` 至少提供 `en_us`，最好补上常用语言；运行时按玩家语言查找，缺省回退 `en_us`。
- 在多个 MC 版本/加载器上都测过再发布；PR 到本仓库的配置会在合并前被复核。
- 保持每个文件 ≤ 2 MB（实际上适配配置通常只有几 KB）。
- 欢迎直接向本仓库提交配置（见 [README 贡献流程](../README_ZH.md)）；自建源更适合：实验性配置、私有整合包定制、或想走独立发布节奏的作者。
