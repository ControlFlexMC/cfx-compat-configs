# 配置字段参考（Config Field Reference）

> 适用版本：**ControlFlex ≥ 0.8.7**（`mod_versions` + `inGameKeys`/`screenKeys`/`overlayKeys` 三段通道模型）。
> 本文是 compat 配置 JSON 的完整字段参考；发布自己的适配源见 [02.build-your-own-compat-source](./02.build-your-own-compat-source_ZH.md)，社区源系统设计见 [03.community-config-repo-design](./03.community-config-repo-design_ZH.md)。

---

## 文件与加载规则

- 配置文件位于 `config/controlflex/compat/{default,mods,user}/` 三层，优先级 `user` > `mods` > `default`；社区源「应用」写入的就是 `user/<mod_id>.json`。
- 配置身份由 JSON 内的 **`mod_id` 字段**决定，而非文件名；`mod_id` 缺失/为空的文件整个被跳过。user 层文件请命名为 `<mod_id>.json`，界面与热重载按此查找。
- 文件级门控（全部满足才加载）：① 目标模组已加载 —— **`mod_id` 本身必须是已安装模组的 ID**；② `dependencies[].mod_id` **全部**已加载（列表为空 = 无额外门控）。任一不满足则整个文件被跳过，日志会区分「模组未加载」与「依赖未加载」。加载器的区分完全由**源目录结构**承担（`forge`/`fabric`/`neoforge` 目录）；旧的按文件 `loader` 字段已删除。
- dotfile（`.` 开头，如 `.applied.json`）不会被当作配置解析。
- 旧格式 `{modid}_keys.json` 会在启动时自动迁移（重命名并保留备份，字段自动转换）。

## 求值模型

每个文件按**模组版本**组织规则：`mod_versions` 数组按顺序求值，**首条匹配即生效**；没有任何条目匹配当前模组版本时**整个配置不生效**（有警告日志）。

## 顶层字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `mod_id` | string | 是 | 配置归属的模组 ID（如 `jei`、`epicfight`）。为空、或**该模组未安装**时整个文件被跳过 —— 它本身就是激活门控的一部分。 |
| `dependencies` | object[] | 否 | 额外依赖门控：数组，每项 `{ "mod_id": "...", "mod_name": "...", "home_pages": [...] }`；运行时读取每项的 `mod_id`（其余字段仅展示），**全部已加载**配置才激活。详见 [dependencies](#dependencies激活门控与依赖展示)。 |
| `contributors` | string[] | 否 | 作者名单，显示在社区配置预览页。 |
| `config_version` | string | 否 | 配置自身的版本号（展示用，无运行时逻辑）。 |
| `mod_versions` | array | 是 | 按模组版本区分的规则列表，见下。**旧字段名 `versions` 不再被接受。** |
| `mod_name`、`home_page` | — | 否 | 纯元数据 —— 供清单生成器与预览页使用，运行时解析器忽略。 |

## `mod_versions[]` 字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|:----:|------|
| `version` | string | 是 | 模组版本匹配器，见[版本匹配](#版本匹配)。**非法匹配器会丢弃整个条目**。 |
| `inGameKeys` | object | 否 | **游戏中**（未打开 Screen）生效的按键。 |
| `screenKeys` | object | 否 | 打开 **Screen（GUI 界面）** 期间生效的按键。 |
| `overlayKeys` | object | 否 | 打开**悬浮层 overlay**（如法术轮盘等叠在 HUD 上的界面）期间生效的按键。 |
| `phasePersistentKeys` | object | 否 | 跨阶段切换保持按键绑定同步，见 [phasePersistentKeys](#phasepersistentkeys)。 |
| `ignoreKeys` | string[] | 否 | 从绑定列表中隐藏动作，见 [ignoreKeys](#ignorekeys)。 |
| `itemSuppressKeys` | object[] | 否 | 主手持有特定物品时屏蔽动作，见 [itemSuppressKeys](#itemsuppresskeys)。 |
| `tips` | object[] | 否 | 绑定行旁的提示文字，见 [tips](#tips)。 |
| `screen` | object | 否 | 按 Screen 定制光标样式与摇杆行为，见 [screen 与 overlay](#screen-与-overlay摇杆--光标)。 |
| `overlay` | object | 否 | 按 overlay 定制光标样式与摇杆行为（键为打开者类名；`"*"` 为模组级兜底）。 |

未列出的字段会被静默忽略。

## 版本匹配

`version` 支持三种写法，按数组顺序求值，**首条匹配即生效**：

| 格式 | 示例 | 语义 |
|------|------|------|
| 通配符 | `""`（也接受 `"(,)"`） | 匹配所有版本 |
| 精确 | `"1.21.1"` | 仅匹配此版本 |
| 区间 | `"[1.0,2.0)"` | `1.0 ≤ v < 2.0`（方括号含端点、圆括号不含） |
| 半开区间 | `"[21.1,)"` / `"(,1.20]"` | `v ≥ 21.1` / `v ≤ 1.20` |

- 比较按点分段数字语义：缺省段视为 `0`、忽略非数字前缀（`v1.0` → `1.0`、`0-beta` → `0`）。
- 区间写法非法（缺括号/缺逗号/端点无法解析/下界大于上界）→ **丢弃整个条目**并记警告。
- **具体区间写在前，通配符 `""` 放最后兜底。**

## dependencies（激活门控与依赖展示）

`dependencies` 取代了旧版的 `required_mod`（该字段已删除，导入旧文件时会被自动剥离）：

```json
"dependencies": [
  { "mod_id": "cfx_compat_epicfight", "mod_name": "Control Flex x Epic Fight",
    "home_pages": ["https://www.curseforge.com/minecraft/mc-mods/cfx-x-epic"] }
]
```

- **激活门控**：列表中每一项的 `mod_id` 都必须已安装，配置才会激活；列表为空 = 无额外门控。
- 结构：**数组**，元素为**对象**。运行时只读取 `mod_id`（大小写不敏感，自动小写化）；`mod_name` / `home_pages` 等仅用于社区预览页展示。元素写成纯字符串会被忽略；`dependencies` 不是数组则整段忽略（有警告日志）。
- **典型用途**：配置需要搭配其他模组才能完整工作时（如 `epicfight` 配置依赖桥接模组 `cfx_compat_epicfight` 提供完整手柄支持），或配置归属于独立的兼容模组。
- 普通配置（`mod_id` 就是目标模组本身）无需填写。

## 三段结构与分发通道（channels）

`inGameKeys` / `screenKeys` / `overlayKeys` 是**「裸键名 → 按键条目」的对象**：

- 裸键名 = `KeyMapping.getName()`，不含 `modid:` 前缀；ControlFlex 内部动作 ID 为 `{modid}:{keyName}`（键名本身不含 modid 时，通过声明归属到配置的模组）。
- 同一按键声明在多段中即为多层成员（并集）；**三段都未声明**的按键默认只属于游戏层。
- 段级 `"channels"` 是**保留键**：为该段所有按键设置默认通道；解析时按键条目自身的 `channels` 优先。
- 段的值**必须是对象**；旧格式的数组写法会被警告并丢弃整段。

```json
"inGameKeys": {
  "channels": ["keyMapping"],
  "key.epicfight.dodge": {},
  "key.epicfight.attack": { "channels": ["keyMapping", "eventBus"],
                            "extraBehaviors": ["suppressLayerSwitch"] }
}
```

按键条目字段：

| 字段 | 说明 |
|------|------|
| `channels` | 数组；**显式 `[]` 表示"该键不分发任何通道"**（未写则继承段默认/并集）。 |
| `extraBehaviors` | 数组，见 [extraBehaviors](#extrabehaviors)。 |

**通道（channels）** —— ControlFlex 向模组传递按键的途径：

| 通道 | 含义 |
|------|------|
| `keyMapping` | 写入 `KeyMapping.setPressed()` / `isDown` 状态（类原版路径）。 |
| `eventBus` | 广播 Forge `InputEvent.Key`（按 tick 合并）。 |
| `glfwPoll` | 把按住状态镜像进合成的 `InputConstants.isKeyDown()`，供直接轮询 GLFW 的模组使用。 |
| `screenInput` | Screen 打开期间注入 `screen.keyPressed/keyReleased`（鼠标键则注入合成点击）。 |
| `virtualKbm` | 经虚拟键鼠注入，等同真实硬件输入。**独占**：取代其余所有通道；不可被用户改写。 |

**段默认通道**（段未写 `channels` 时）：

| 段 | 默认通道 |
|----|----------|
| `inGameKeys` | `keyMapping`、`eventBus` |
| `screenKeys` | `keyMapping`、`screenInput` |
| `overlayKeys` | `keyMapping`、`eventBus` |

按键属于多段时，生效通道为各段默认的并集；用户在界面里的通道覆盖优先于配置。

典型场景：

- 模组**双触发**（两条路径都监听）→ 只保留 `keyMapping`。
- 模组**只监听 Forge 事件** → `["eventBus"]`。
- **长按开菜单且模组轮询 GLFW** → 加 `glfwPoll`。

## extraBehaviors

按键条目级行为标记（数组，当前仅一个值）：

| 值 | 含义 |
|----|------|
| `suppressLayerSwitch` | 该动作的绑定被**按住**期间，抑制层切换（进入 shift 层）动作；保存时该绑定强制为 **HOLD** 模式。适用于模组自带的"修饰键"类按键（如 Iron's Spells 'n Spellbooks 的 `key.irons_spellbooks.spell_bar_modifier`）。 |

显式 `[]` 表示明确不启用。

## phasePersistentKeys

声明某按键的绑定在阶段切换时保持跟随：

```json
"inGameKeys":  { "key.irons_spellbooks.spell_wheel": {} },
"overlayKeys": { "key.irons_spellbooks.spell_wheel": {} },
"phasePersistentKeys": { "key.irons_spellbooks.spell_wheel": ["inGame", "overlay"] }
```

- 仅支持两种配对：`["inGame", "overlay"]` 与 `["inGame", "screen"]`（源必须是 `inGame`，目标只有一个）。
- **配对生效的前提是该键同时声明在两段中**（`inGameKeys` **和**目标段）；仅靠多段并集的隐式成员资格不算，否则日志警告并忽略配对。
- 运行时目标层的绑定被软锁定并**从游戏层实时推导**（不落盘复制）—— 按住的按钮跨阶段切换时保持按下，避免长按菜单在 overlay/Screen 出现时闪退。
- 此类动作的绑定为 HOLD 模式；**物品抑制对它们跳过**。
- 在绑定界面编辑目标层会写入快照绑定并解锁；重置该键恢复锁定与推导。

## ignoreKeys

从绑定 UI 隐藏动作（调试键、作弊键、重复键）：

```json
"ignoreKeys": ["key.epicfight.config"]
```

解析时自动补上 `modid:` 前缀与动作 ID 匹配。

## itemSuppressKeys

**主手物品**匹配时屏蔽动作。典型场景：模组对特定物品接管了输入（如 Epic Fight 战斗模式下攻击/交互由模组的连击与武器技能系统处理），此时屏蔽通用动作避免相互干扰：

```json
"itemSuppressKeys": [
  { "item": "efn:yamato_dmc*", "playerState": ["epicfight:battle_mode"], "suppressActions": ["use"] },
  { "tag": "minecraft:swords", "playerState": ["epicfight:battle_mode"], "suppressActions": ["attack", "use"] }
]
```

| 字段 | 说明 |
|------|------|
| `item` | 物品 ID（`modid:item_id`），支持 `*` 通配；与 `tag` 二选一。 |
| `tag` | 物品标签；与 `item` 二选一。 |
| `playerState` | 可选 `modId:状态` 列表（OR 关系）；空表示仅看物品。未知状态记警告并视为不匹配。 |
| `suppressActions` | 要屏蔽的动作 —— 内置短名（`attack`、`use`）或完整动作 ID。 |

每 tick 对主手物品求值；`phasePersistentKeys` 命中的动作不受其影响。

## tips

绑定行提示：

```json
"tips": [
  { "key": "key.epicfight.weapon_innate_skill",
    "text": { "en_us": "Bind to the same button as Attack; use HOLD mode.",
              "zh_cn": "请绑定为与「攻击」相同的按键，并使用 HOLD 模式。" } }
]
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `key` | string | KeyMapping 名称（不含 `mod_id:` 前缀）。 |
| `text` | object | Minecraft 语言代码 → 提示文案。 |

- 语言代码**无固定白名单**，写什么支持什么；运行时按玩家语言查找，回退 `en_us`；连 `en_us` 都没有则不显示。
- **务必提供 `en_us`**，有精力再补 `zh_cn` 等。

## screen 与 overlay（摇杆 & 光标）

按 Screen / overlay 定制光标与摇杆行为。键为**全限定类名** —— Screen 用 `screen.getClass().getName()`；overlay 用**打开者类名**（`"*"` 作为模组级兜底）：

```json
"screen": {
  "com.dragonminez.client.gui.UtilityMenuScreen": {
    "leftStick":  { "behavior": "VIRTUAL_MOUSE" },
    "rightStick": { "behavior": "RADIAL_PATH", "threshold": 0.5, "cursorRadius": 90 }
  }
},
"overlay": {
  "io.redspace.ironsspellbooks.gui.overlays.SpellWheelOverlay": {
    "rightStick": { "behavior": "RADIAL_PATH", "threshold": 0.3, "cursorRadius": 40, "showCursor": false }
  }
}
```

`behavior` 取值：

| `behavior` | 含义 |
|------------|------|
| `DEFAULT` | 引擎默认（左摇杆增量虚拟鼠标；GUI 下右摇杆无动作） |
| `VIRTUAL_MOUSE` | 摇杆驱动增量虚拟光标 |
| `RADIAL_PATH` | 以屏幕中心为原点的极坐标光标（轮盘类菜单） |
| `DISABLED` | 忽略摇杆轴；摇杆**按下**类绑定仍有效 |

`StickEntry` 参数（均可选）：

| 参数 | 默认 | 说明 |
|------|------|------|
| `threshold` | `0.5` | 摇杆死区 |
| `cursorRadius` | `100` | 相对屏幕中心的半径（逻辑像素 × GUI 缩放） |
| `cursorSpeed` | `1.0` | 光标速度（限幅 `0.1–3.0`） |
| `showCursor` | `true` | 是否绘制光标（`false` 时仍跟踪位置，只隐藏绘制） |
| `keepLastPosition` | `true` | 松杆是否停在原地（旧字段 `returnToCenter: false` 的对应物） |
| `angleBias` | `1.0` | 角度灵敏度 |

`ScreenEntry` / overlay 条目还支持：

- `cursorStyle`：`"system"`（OS 光标）/ `"bedrock"` / `"hand"`；解析顺序为 当前 overlay 条目 → 当前 Screen 条目 → 全局。
- `disabled: true`：该界面/悬浮层完全退出接管，**不再回退**到其他配置。

解析规则：user 层优先于内置层；具体 overlay 条目优先于同模组的 `"*"`；命中条目缺少请求侧（left/right）时继续尝试下一条配置。任何非 `DEFAULT` 摇杆行为都会使该摇杆的视角/移动绑定在该上下文期间让位给模组。

## 从旧格式迁移（≤ 0.8.5）

ControlFlex ≥ 0.8.7 会在启动时自动迁移旧文件；手动维护可对照：

| 旧格式（≤ 0.8.5） | 新格式（≥ 0.8.7） |
|------------------|-------------------|
| `versions` | `mod_versions` |
| `loader`: `"forge"`（字符串，`"both"`） | **已删除**（不再解析，导入旧文件时自动剥离；加载器区分只看源目录） |
| `required_mod`: `"x"` | `dependencies: [{ "mod_id": "x" }]`（旧字段已删除，导入旧文件时自动剥离） |
| `guiKeys: ["k"]` | `screenKeys: { "k": {} }` |
| `specialActionKeys` 的 `GLFW_COMPAT` | 按键 `channels: ["glfwPoll"]` |
| `specialActionKeys` 的 `PHASE_PERSISTENT` | `phasePersistentKeys: { "k": ["inGame","screen"] }` + 在两段中声明该键 |
| `skipForgeKeys: ["k"]` | `inGameKeys.k.channels = ["keyMapping"]` |
| `skipVanillaKeys: ["k"]` | 仅 `channels: ["eventBus"]` |
| `leftStick`/`rightStick` 数组（含 `screens`、`mode`） | `screen` 对象（键为类名）；`mode` → `behavior` |
| `mode: "RADIAL_CURSOR"` | `behavior: "RADIAL_PATH"` |
| `returnToCenter: false` | `keepLastPosition: true` |
| ——（原无） | `overlayKeys`、`overlay` 按 overlay 摇杆配置、目标为 overlay 的 `phasePersistentKeys` |

## 常见陷阱清单

1. 三段结构（`inGameKeys`/`screenKeys`/`overlayKeys`）必须是**对象**，写成数组会被整段丢弃。
2. 段对象里的 `channels` 是**保留键**，会被当作段默认通道而非按键名。
3. 按键条目的 `channels: []` / `extraBehaviors: []` 是**有意义的显式空**（该键不分发/不启用行为），与不写字段不同。
4. `mod_versions` 首条匹配生效 —— 区间顺序写错会让宽泛条目拦截所有版本；无条目匹配则整个配置无效。
5. `version` 匹配器非法会**丢弃整个条目**（不只是该字段）。
6. 归属看 JSON 的 `mod_id`，不看文件名；但 user 层文件必须命名 `<mod_id>.json`，否则界面与热重载找不到。
7. `phasePersistentKeys` 需要双段声明才生效；只写配对不声明两段会被忽略（有警告日志）。
8. 校验 JSON 语法（无尾逗号）、UTF-8 编码；默认通道行为异常时才添加 `channels` 覆盖。
9. `mod_id` 必须是已安装模组的 ID；`dependencies` 元素必须是对象（纯字符串会被忽略）—— 两者都参与激活门控。
