# Config Field Reference

> Applies to **ControlFlex ≥ 0.8.7** (the `mod_versions` + `inGameKeys`/`screenKeys`/`overlayKeys` three-section channel model).
> This is the complete field reference for compat config JSON. For publishing your own source see [02.build-your-own-compat-source](./02.build-your-own-compat-source.md); for the community source system design see [03.community-config-repo-design](./03.community-config-repo-design.md).

---

## Files & loading rules

- Config files live in the three layers `config/controlflex/compat/{default,mods,user}/`, priority `user` > `mods` > `default`; the community source "Apply" writes into `user/<mod_id>.json`.
- A config's identity comes from the **`mod_id` field inside the JSON**, not the filename; files with a missing/empty `mod_id` are skipped entirely. Name user-layer files `<mod_id>.json` — the UI and hot-reload look them up by that name.
- File-level gates (all must pass to load): ① the target mod is loaded — **`mod_id` itself must be an installed mod's ID**; ② **every** `dependencies[].mod_id` is loaded (empty list = no extra gate). If a check fails the whole file is skipped; logs distinguish "mod not loaded" from "dependencies not loaded". Loader separation is handled entirely by the **source directory layout** (`forge`/`fabric`/`neoforge`); the legacy per-file `loader` field has been removed.
- Dotfiles (starting with `.`, e.g. `.applied.json`) are never parsed as configs.
- Legacy `{modid}_keys.json` files are auto-migrated on startup (renamed with a backup, fields converted).

## Evaluation model

Each file organizes rules **per mod version**: the `mod_versions` array is evaluated in order, **first match wins**; if no entry matches the installed mod version, the **entire config has no effect** (warning logged).

## Top-level fields

| Field | Type | Required | Description |
|-------|------|:--------:|-------------|
| `mod_id` | string | Yes | Mod ID owning this config (e.g. `jei`, `epicfight`). Empty, or **the mod not installed** → the whole file is skipped — it is part of the activation gate itself. |
| `dependencies` | object[] | No | Extra dependency gate: an array of `{ "mod_id": "...", "mod_name": "...", "home_pages": [...] }`; at runtime each entry's `mod_id` is read (other fields are display-only), and **all of them must be loaded** for the config to activate. See [dependencies](#dependencies-activation-gate--dependency-display). |
| `contributors` | string[] | No | Author names, shown on the community-config preview page. |
| `config_version` | string | No | Version of this config itself (display only, no runtime logic). |
| `mod_versions` | array | Yes | Version-specific rule sets, see below. **The legacy name `versions` is no longer accepted.** |
| `mod_name`, `home_page` | — | No | Metadata only — used by the manifest generator & preview UI, ignored by the runtime parser. |

## `mod_versions[]` fields

| Field | Type | Required | Description |
|-------|------|:--------:|-------------|
| `version` | string | Yes | Mod-version matcher, see [Version matching](#version-matching). An **invalid matcher discards the whole entry**. |
| `inGameKeys` | object | No | Keys active **in game** (no Screen open). |
| `screenKeys` | object | No | Keys active while a **Screen** (GUI) is open. |
| `overlayKeys` | object | No | Keys active while an **overlay** (e.g. spell wheel drawn over the HUD) is open. |
| `phasePersistentKeys` | object | No | Keep a key's binding synced across a phase switch, see [phasePersistentKeys](#phasepersistentkeys). |
| `ignoreKeys` | string[] | No | Hide actions from the binding UI, see [ignoreKeys](#ignorekeys). |
| `itemSuppressKeys` | object[] | No | Suppress actions while holding specific items, see [itemSuppressKeys](#itemsuppresskeys). |
| `tips` | object[] | No | Hint text shown next to bindings, see [tips](#tips). |
| `screen` | object | No | Per-Screen cursor style + stick behavior, see [screen & overlay](#screen--overlay-stick--cursor). |
| `overlay` | object | No | Per-overlay cursor style + stick behavior (keyed by opener class; `"*"` = mod-level fallback). |

Unlisted fields are silently ignored.

## Version matching

The `version` field supports three forms; entries are evaluated **in array order**, first match wins:

| Format | Example | Meaning |
|--------|---------|---------|
| Wildcard | `""` (also `"(,)"`) | Matches all versions |
| Exact | `"1.21.1"` | Exact match |
| Interval | `"[1.0,2.0)"` | `1.0 ≤ v < 2.0` (brackets inclusive, parens exclusive) |
| Unbounded | `"[21.1,)"` / `"(,1.20]"` | `v ≥ 21.1` / `v ≤ 1.20` |

- Comparison is numeric on dot-separated segments: missing segments = `0`, non-digit prefixes stripped (`v1.0` → `1.0`, `0-beta` → `0`).
- Malformed intervals (missing bracket/comma, unparseable bounds, lower > upper) → **the whole entry is discarded** with a warning.
- **Put specific intervals first and a `""` wildcard last as fallback.**

## dependencies (activation gate & dependency display)

`dependencies` replaces the legacy `required_mod` (that field has been removed; it is stripped automatically when importing old files):

```json
"dependencies": [
  { "mod_id": "cfx_compat_epicfight", "mod_name": "Control Flex x Epic Fight",
    "home_pages": ["https://www.curseforge.com/minecraft/mc-mods/cfx-x-epic"] }
]
```

- **Activation gate**: every entry's `mod_id` must be installed for the config to activate; an empty list = no extra gate.
- Structure: an **array** of **objects**. Runtime reads only `mod_id` (case-insensitive, lowercased); `mod_name` / `home_pages` etc. are display-only for the community preview page. Elements written as plain strings are ignored; a non-array `dependencies` is ignored entirely (warning logged).
- **Typical use**: configs that need other mods to work fully (e.g. the `epicfight` config depends on the bridge mod `cfx_compat_epicfight` for full gamepad support), or configs owned by a standalone compatibility mod.
- Ordinary configs (where `mod_id` is the target mod itself) don't need it.

## The three sections & dispatch channels

`inGameKeys` / `screenKeys` / `overlayKeys` are **objects mapping bare key names to a per-key entry**:

- Bare key name = `KeyMapping.getName()` without the `modid:` prefix; internally actions are namespaced `{modid}:{keyName}` (keys whose name doesn't embed the modid are attributed to the config's mod via its declarations).
- A key declared in several sections is a member of all of them (union); a key **declared in none** defaults to in-game only.
- The section-level `"channels"` key is **reserved**: it sets the default channels for every key in that section; a per-key `channels` takes precedence.
- Section values **must be objects**; the legacy array form is warned about and the whole section dropped.

```json
"inGameKeys": {
  "channels": ["keyMapping"],
  "key.epicfight.dodge": {},
  "key.epicfight.attack": { "channels": ["keyMapping", "eventBus"],
                            "extraBehaviors": ["suppressLayerSwitch"] }
}
```

Per-key entry fields:

| Field | Description |
|-------|-------------|
| `channels` | Array; an **explicit `[]` means "dispatch nothing for this key"** (omitting it inherits section defaults/union). |
| `extraBehaviors` | Array, see [extraBehaviors](#extrabehaviors). |

**Channels** — how ControlFlex delivers a button press to the mod:

| Channel | Meaning |
|---------|---------|
| `keyMapping` | Write `KeyMapping.setPressed()` / `isDown` state (vanilla-like path). |
| `eventBus` | Broadcast a Forge `InputEvent.Key` (merged per tick). |
| `glfwPoll` | Mirror the hold into synthetic `InputConstants.isKeyDown()` state for mods that poll GLFW directly. |
| `screenInput` | While a Screen is open, feed `screen.keyPressed/keyReleased` (or a synthetic mouse click for mouse-bound keys). |
| `virtualKbm` | Inject through the virtual keyboard/mouse as real hardware input. **Exclusive**: replaces all other channels; not user-overridable. |

**Section defaults** (when a section writes no `channels`):

| Section | Default channels |
|---------|------------------|
| `inGameKeys` | `keyMapping`, `eventBus` |
| `screenKeys` | `keyMapping`, `screenInput` |
| `overlayKeys` | `keyMapping`, `eventBus` |

A key in several sections gets the union of those sections' defaults; the user's in-UI channel overrides beat the config.

Typical fixes:

- Mod **fires twice** (listens on both paths) → keep only `keyMapping`.
- Mod **only listens to Forge events** → `["eventBus"]`.
- **Hold-to-open menu that polls GLFW** → add `glfwPoll`.

## extraBehaviors

Per-key behavior flags (array, one value today):

| Value | Meaning |
|-------|---------|
| `suppressLayerSwitch` | While that action's binding is **held**, ControlFlex suppresses the layer-switch (shift-layer enter) action; the binding is forced to **HOLD** mode on save. Use for modded modifier-style keys (e.g. Iron's Spells 'n Spellbooks' `key.irons_spellbooks.spell_bar_modifier`). |

An explicit `[]` means explicitly disabled.

## phasePersistentKeys

Declares that a key's binding should follow it across a phase switch:

```json
"inGameKeys":  { "key.irons_spellbooks.spell_wheel": {} },
"overlayKeys": { "key.irons_spellbooks.spell_wheel": {} },
"phasePersistentKeys": { "key.irons_spellbooks.spell_wheel": ["inGame", "overlay"] }
```

- The only valid pairings are `["inGame", "overlay"]` and `["inGame", "screen"]` (source must be `inGame`, exactly one destination).
- **The pairing only takes effect if the key is declared in both sections** (`inGameKeys` **and** the destination section); implicit membership via the union doesn't count — otherwise a warning is logged and the pairing is ignored.
- At runtime the destination layer's binding is soft-locked and **derived at runtime from the game layers** (never persisted as a copy) — a held button stays held across the transition, preventing hold-to-open menus from flickering closed when an overlay/screen appears.
- Bindings for these actions are materialized as HOLD; **item suppression is skipped** for them.
- Editing the destination layer in the binding UI writes a snapshot binding and unlocks it; resetting the key restores the lock and derivation.

## ignoreKeys

Hide actions from the binding UI (debug/cheat/duplicate keys):

```json
"ignoreKeys": ["key.epicfight.config"]
```

The `modid:` prefix is added automatically when matching against action IDs.

## itemSuppressKeys

Suppress actions while the **main-hand item** matches. Typical scenario: the mod takes over input for specific items (e.g. in Epic Fight battle mode, attack/interact are handled by the mod's combo & weapon-skill systems) — suppress the generic actions to keep them from interfering:

```json
"itemSuppressKeys": [
  { "item": "efn:yamato_dmc*", "playerState": ["epicfight:battle_mode"], "suppressActions": ["use"] },
  { "tag": "minecraft:swords", "playerState": ["epicfight:battle_mode"], "suppressActions": ["attack", "use"] }
]
```

| Field | Description |
|-------|-------------|
| `item` | Item ID (`modid:item_id`); `*` wildcard supported. Mutually exclusive with `tag`. |
| `tag` | Item tag. Mutually exclusive with `item`. |
| `playerState` | Optional `modId:state` list (OR); empty = always when the item matches. Unknown states warn and count as no-match. |
| `suppressActions` | Action short names (`attack`, `use`) or full action IDs to block. |

Evaluated per tick against the main-hand item; actions matched by `phasePersistentKeys` are exempt.

## tips

Hints shown on binding rows:

```json
"tips": [
  { "key": "key.epicfight.weapon_innate_skill",
    "text": { "en_us": "Bind to the same button as Attack; use HOLD mode.",
              "zh_cn": "请绑定为与「攻击」相同的按键，并使用 HOLD 模式。" } }
]
```

| Field | Type | Description |
|-------|------|-------------|
| `key` | string | KeyMapping name (without the `mod_id:` prefix). |
| `text` | object | Minecraft language code → hint string. |

- Language codes have **no fixed whitelist**; runtime uses the player's language, falling back to `en_us`; if `en_us` is missing too, no tip is shown.
- **Always include `en_us`**; add `zh_cn` etc. when you can.

## screen & overlay (stick & cursor)

Customize cursor/stick behavior while a specific Screen or overlay is open. Keys are **fully qualified class names** — `screen.getClass().getName()` for Screens; for overlays the **opener class** (with `"*"` as a mod-level fallback):

```json
"screen": {
  "com.dragonminez.client.gui.UtilityMenuScreen": {
    "leftStick":  { "behavior": "VIRTUAL_MOUSE" },
    "rightStick": { "behavior": "RADIAL_PATH", "threshold": 0.5, "cursorRadius": 90 }
  }
},
"overlay": {
  "io.redspace.ironsspellbooks.gui.overlays.SpellWheelOverlay": {
    "rightStick": { "behavior": "RADIAL_PATH", "threshold": 0.3, "cursorRadius": 40, "showCursor": false }
  }
}
```

`behavior` values:

| `behavior` | Meaning |
|------------|---------|
| `DEFAULT` | Engine default (incremental virtual mouse on left stick; nothing on right stick in GUI) |
| `VIRTUAL_MOUSE` | Stick drives the incremental virtual cursor |
| `RADIAL_PATH` | Polar cursor from screen center (radial menus) |
| `DISABLED` | Axis ignored; stick-click bindings still work |

`StickEntry` parameters (all optional):

| Parameter | Default | Description |
|-----------|---------|-------------|
| `threshold` | `0.5` | Stick deadzone |
| `cursorRadius` | `100` | Distance from screen center (logical pixels × GUI scale) |
| `cursorSpeed` | `1.0` | Cursor speed (clamped `0.1–3.0`) |
| `showCursor` | `true` | Draw the cursor (`false` still tracks position, only hides the drawing) |
| `keepLastPosition` | `true` | Stay in place on stick release (counterpart of legacy `returnToCenter: false`) |
| `angleBias` | `1.0` | Angle sensitivity |

`ScreenEntry` / overlay entries also support:

- `cursorStyle`: `"system"` (OS cursor) / `"bedrock"` / `"hand"`; resolution order: active overlay entry → current Screen entry → global.
- `disabled: true`: opt this screen/overlay out entirely, **no fallback** to other configs.

Resolution: user layer before built-ins; a specific overlay entry beats `"*"` of the same mod; a hit that lacks the requested side (left/right) falls through to the next config. Any non-`DEFAULT` stick behavior makes the stick's camera/movement bindings yield to the mod while that context is active.

## Migrating from the legacy format (≤ 0.8.5)

ControlFlex ≥ 0.8.7 auto-migrates old files on startup; if you maintain configs by hand:

| Legacy (≤ 0.8.5) | Current (≥ 0.8.7) |
|------------------|-------------------|
| `versions` | `mod_versions` |
| `loader`: `"forge"` (string, `"both"`) | **removed** (no longer parsed, stripped automatically on import; loader separation is by source directory only) |
| `required_mod`: `"x"` | `dependencies: [{ "mod_id": "x" }]` (legacy field removed, stripped automatically on import) |
| `guiKeys: ["k"]` | `screenKeys: { "k": {} }` |
| `specialActionKeys` flag `GLFW_COMPAT` | per-key `channels: ["glfwPoll"]` |
| `specialActionKeys` flag `PHASE_PERSISTENT` | `phasePersistentKeys: { "k": ["inGame","screen"] }` + declare the key in both sections |
| `skipForgeKeys: ["k"]` | `inGameKeys.k.channels = ["keyMapping"]` |
| `skipVanillaKeys: ["k"]` | `channels: ["eventBus"]` only |
| `leftStick`/`rightStick` arrays with `screens`, `mode` | `screen` object keyed by class name; `mode` → `behavior` |
| `mode: "RADIAL_CURSOR"` | `behavior: "RADIAL_PATH"` |
| `returnToCenter: false` | `keepLastPosition: true` |
| — (didn't exist) | `overlayKeys`, `overlay` per-overlay stick config, `phasePersistentKeys` with overlay destination |

## Gotchas checklist

1. The three sections (`inGameKeys`/`screenKeys`/`overlayKeys`) must be **objects** — the array form is dropped with a warning.
2. `channels` inside a section object is a **reserved key** — it's read as the section default, never as a key name.
3. Per-key `channels: []` / `extraBehaviors: []` are **meaningful explicit empties** (dispatch nothing / no behavior) — different from omitting the field.
4. `mod_versions` is first-match-wins — a mis-ordered broad interval intercepts every version; no matching entry means the whole config is inert.
5. An invalid `version` matcher discards **the whole entry**, not just the field.
6. Identity comes from the JSON's `mod_id`, not the filename; but user-layer files must be named `<mod_id>.json` or the UI/hot-reload can't find them.
7. `phasePersistentKeys` requires the dual-section declaration to work; the pairing alone is ignored (warning logged).
8. Validate JSON syntax (no trailing commas) and UTF-8 encoding; add `channels` overrides only when the default behavior misbehaves.
9. `mod_id` must be an installed mod's ID; `dependencies` elements must be objects (plain strings are ignored) — both participate in the activation gate.
