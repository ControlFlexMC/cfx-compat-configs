# 社区配置仓库（Community Config Repo）— 设计文档

> 日期: 2026-08-15
> 前置: `repo-config.md`（远端配置分发方案，2026-08-14 已评审通过；本稿为其在 ControlFlex 的落地方案，标注了所有需求差异改编）；`2026-08-11-mod-adaptation-design.md`（列表页/详情页 UI 骨架）；`2026-08-12-mod-detail-page-design.md`（详情页）；`2026-08-13-compat-config-format-design.md`（compat 配置 JSON 格式）
> 分支: `feature/repo-config`

---

## 1. 背景与目标

通过 Git 仓库（经 jsDelivr CDN / raw.githubusercontent 静态 HTTP 暴露）分发社区适配配置。客户端维护多源列表，同步远端清单到本地（按需下载、内容寻址缓存、可离线使用），用户浏览并一键 Apply 社区方案到 user 生效层。

**需求映射**（用户需求 → 本文档章节）：

| # | 需求 | 章节 |
|---|---|---|
| 1 | 模组适配 Panel 右上角「更多」菜单：编辑源列表 / 同步最新配置 | §8.1–8.3 |
| 2 | 列表页卡片右侧显示该 mod_id 的社区可选方案数 | §8.4 |
| 3 | 默认源两个（CDN 在前） | 决策 1、§5.2 |
| 4 | URL 自动拼接 mc 版本 + 加载器 | 决策 5–7、§4.1 |
| 5 | 详情页常驻横幅 + 社区方案列表 | §8.5–8.6 |
| 6 | 只读预览页 + Apply + 旧配置备份（时间戳） | §8.7、§7.3 |

**目标：**

- 支持多个配置源；两个官方内置源（CDN 在前），用户可添加第三方源。
- 多源并集：所有**启用**源的清单合并为一张全局目录；同一 `mod_id` 的不同内容（sha256）是平行变体，全部可见、由用户挑选。
- 内容寻址存储（CAS）：按 sha256 落盘，跨源去重；同一 sha256 被多源提供时合并为镜像 URL 列表，下载任一成功即可。
- 按需/懒加载：同步只刷新清单，内容文件在预览/应用时才下载。
- repo 层是可选配置仓库（目录），**不参与生效解析**（`user > default` 覆盖链不变）；Apply 是唯一生效入口。
- 纯静态文件方案：发布端只需 git push，无需服务器。

**非目标（本期不做）：** 清单签名 / TUF 式防篡改（将来扩展）；自动 GC（仅保留 API，无 UI 入口）；字段级配置合并（层间为整文件覆盖）；XML 清单；跨加载器同步（仅同步当前加载器，见决策 5）；neoforge 平台实现；备份恢复 UI；依赖自动安装；独立浏览仓库目录（社区方案仅经已安装 mod 的徽章/横幅入口浏览）。

## 2. 决策记录

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 默认源 | 两个官方内置源（代码 hardcode 种子，首次运行播种进 `sources.json`），**CDN 在前**：① `https://cdn.jsdelivr.net/gh/ControlFlexMC/cfx-compat-configs@main` ② `https://raw.githubusercontent.com/ControlFlexMC/cfx-compat-configs/refs/heads/main` |
| 2 | 内置源编辑权 | **可禁用、可排序、不可删除**（删除按钮置灰）；弹窗提供「恢复默认源」= 两个内置源恢复存在 + 启用 + 默认顺序（CDN 在前），用户自添源保留其后，不删除用户源 |
| 3 | sources.json 格式 | **对象数组** `{baseUrl, enabled, builtin}`（改编自 repo-config.md 的纯 baseUrl 数组——原方案"配上即启用"无法表达"禁用源"需求）；`builtin` 字段仅程序写入，用户添加的源 `builtin=false` |
| 4 | 源 id 推导 | 照搬 repo-config.md：全小写；host 为 `cdn.jsdelivr.net` 且 path[0] 为 `gh` → `${path[1]}@${host}`；有 path 段 → `${path[0]}@${host}`；无 path 段 → `${host}`；冲突按列表顺序加 `-1`、`-2`。端口不参与 id（同 host 不同端口靠冲突后缀区分） |
| 5 | 清单 URL | `{baseUrl}/{mcVersion}/{loader}/manifest.json`——repo-config.md 的 `<version>/<分类>` 在 ControlFlex 落地为 **MC 版本目录 + 加载器目录**；无布局版本常量层（需求 4 的 URL 模板为准） |
| 6 | mc 版本检测 | `SharedConstants.getCurrentVersion().getName()`（如 `1.20.1`），精确匹配远端目录名；代码库当前无此检测，需新增。版本目录缺失的降级匹配留作将来扩展 |
| 7 | 同步范围 | **仅同步当前加载器**（分类集 = `{Services.PLATFORM.getLoaderName()}`；fabric 实例只拉 fabric 清单）；URL 模板不变，换实例自动拼不同 loader |
| 8 | 多源并集 | 仅启用源 + 有效清单副本参与并集；同一 mod_id 的不同 sha256 = 平行变体共存；同一 sha256 被多源提供 = 镜像 URL 列表（按源列表顺序尝试） |
| 9 | CAS 落盘 | `repo/content/<mod_id>/<sha256>.json`（全长 64 hex），文件不可变、文件名即内容哈希；同一 mod_id 多变体共存；同步永不自动删 content |
| 10 | 懒加载时机 | 同步零内容下载；**打开预览页时 ensureContent**（改编：repo-config.md 为"选中应用时下载"，但预览页必须展示内容） |
| 11 | apply 语义 | ensureContent → **旧 user 文件先备份**到 `backup/<mod_id>-<yyyyMMdd-HHmmss>.json`（本地时区；需求 6；改编自 repo-config.md 的"直接覆盖"）→ 原子覆盖 `user/<mod_id>.json` → 更新 `.applied.json` → `ModCompatManager.reloadUserConfig(modId)` 生效；生效仍受现有 `required_mod`/`loader`/`versions` 校验门控，不满足则自然不激活（无需新逻辑） |
| 12 | 应用追踪 | `user/.applied.json` 记录 `mod_id → 已应用 sha256`；展示三态：`已应用`（现场哈希与记录匹配）/ `已手动修改`（失配）/ `未追踪`（无记录）；content 文件缺失时跳过对比、仅显示"已应用" |
| 13 | 生效解析 | `user > default` 覆盖链**不变**，repo 不参与；撤销应用 = 手动删 `user/<mod_id>.json` 回退 default 层 |
| 14 | 同步触发 | 启动后异步静默同步（不阻塞启动，本地缓存先行）；手动「同步最新配置」与启动同步共用**单例 job**——job 在跑则 attach 展示实时状态、绝不重启（需求 1.2 "后台运行后重新拉起不重启"），不在跑则新起 |
| 15 | 404 语义 | 源无当前 `{mcVersion}/{loader}` 目录（404）→ **info 级**"该源无当前版本清单"，不算同步失败；旧副本保留继续参与并集。单分类模型下无"全分类失败才算源失败"的区分，源同步失败 = 清单请求网络失败/解析失败/超限 |
| 16 | 下载限制 | 单文件（含清单）2MB 流式限量，超限视为无效配置直接丢弃、不重试；连接超时 5s / 读取超时 30s；跟随 301/302 重定向，拒绝 https→http 降级 |
| 17 | 清理 | `gc()` 仅提供 API（孤儿变体 + 孤儿 manifest 目录 + 残留 tmp），本轮**无 UI 入口**；删源只清理其 manifest 目录，content 归手动 gc |
| 18 | 预览页形态 | **结构化只读视图**：元数据区 + 复用 ModDetailScreen 三 Tab（bindings/screen/overlay）渲染样式的只读列表，无任何编辑入口 |
| 19 | 列表徽章 | 列表页卡片 chevron 左侧渲染计数 pill（`countVariants(modId) > 0` 才显示）；详情页横幅**常驻**（含 N=0 状态，N=0 不可点击） |
| 20 | 测试钩子 | 系统属性 `controlflex.repo.officialBaseUrl` 可重定向内置官方源（仅测试用，生产不设），测试不访问真实外网 |
| 21 | HTTP 实现 | `java.net.http.HttpClient`（JDK 17 可用，流式限量 2MB）；代码库当前无任何网络代码，此层从零新建 |

## 3. 总体架构

新包 `com.ifels.controlflex.repo`，五组件 + 一个 job，职责单一、可独立测试：

1. **RepoSourceManager（源管理）** — 读写 `repo/sources.json`；播种内置源；推导源 id；增/删/禁/排/恢复默认；原子写。
2. **RepoHttpClient（下载）** — HTTP GET；流式限量 2MB；重定向跟随与 https→http 降级拒绝；超时控制。
3. **RepoSyncEngine（同步与内容获取）** — `syncSource`：拉清单→校验→原子写副本 + 状态（零内容下载）；`ensureContent`：多 URL failover 下载→哈希校验→原子写 content；`gc`：孤儿清理；源级互斥锁。
4. **RepoCatalogIndex（并集索引）** — 从全部启用源的清单副本构建内存映射 `mod_id → { sha256 → {urls, 元数据, providers} }`；提供 `countVariants(modId)` / `listVariants(modId)`。无持久化，清单副本即真相，同步/源编辑后重建。
5. **RepoConfigApplier（应用）** — `apply(modId, sha256)`：ensureContent → 备份 → 覆盖 user → 更新 `.applied.json` → 调 `ModCompatManager.reloadUserConfig(modId)`。
6. **RepoSyncJob（单例后台任务）** — 状态机 `IDLE/RUNNING/FINISHED/FAILED/CANCELLED` + 进度 `(doneSources/totalSources, currentSource, currentStage)` + 失败列表；协作式取消（仿 `ModJarScanner` 的 cancelled 标志）；**生命周期挂在 service 层而非 UI 层**（后台运行 = 关弹窗 job 继续，再开 = attach）。

repo 层与现有兼容层的唯一衔接点：apply 成功后调 `ModCompatManager.reloadUserConfig(modId)`。`ModCompatManager` 现有加载链路（`user > mods > default`）**不改动**。

## 4. 存储布局

### 4.1 远端仓库（发布端约定）

baseUrl 指向仓库根；MC 版本目录隔离、加载器目录分治：

```
<repo-root>/
├── 1.20.1/                 # MC 版本
│   ├── forge/              # 加载器：forge / fabric / neoforge
│   │   ├── manifest.json   # 该加载器下的 mods 配置清单
│   │   └── mods/
│   │       └── <mod1>.json # mod 详细配置（清单 path 指向它们）
│   └── fabric/
│       ├── manifest.json
│       └── mods/
└── 1.21.1/
    └── neoforge/
        ├── manifest.json
        └── mods/
```

清单 URL = `{baseUrl}/{mcVersion}/{loader}/manifest.json`；内容 URL = `{baseUrl}/{mcVersion}/{loader}/{path}`（`path` 相对清单所在目录，如 `mods/mod1.json`）。

### 4.2 本地目录

```
config/controlflex/compat/
├── default/                            # 内置兜底配置（现状，只读）
├── mods/                               # cfx-* 兼容模组提供（现状，只读）
├── repo/                               # 社区配置仓库（新增，不参与生效解析）
│   ├── sources.json                    # 全部源（含内置），见 §5.2
│   ├── manifest/<源id>/
│   │   ├── .state.json                 # 每源状态，见 §5.3
│   │   └── manifest.json               # 远端 {mcVersion}/{loader}/manifest.json 逐字节副本
│   └── content/<mod_id>/<sha256>.json  # CAS 内容寻址存储（跨源共享、不可变）
├── backup/                             # apply 备份（新增）
│   └── <mod_id>-<yyyyMMdd-HHmmss>.json
└── user/                               # 生效层（现状）+ 应用追踪（新增）
    ├── <mod_id>.json
    └── .applied.json                   # 见 §5.4
```

- content 文件不可变：存在且哈希相符即已下载（文件系统即状态），永不覆盖；远端更新表现为新增变体文件。
- `mod_id`（正则 `[a-z0-9_-]+`）直接作目录名，校验是硬前提；清单 `path` 不落盘、只拼 URL，路径安全校验保留（拒绝绝对路径、`..`）。
- 清单副本与状态的职责分离：`manifest.json` 是远端逐字节副本（与 `.state.json` 的 `manifestSha256` 严格对应），客户端不注入本地字段；baseUrl 是客户端概念，唯一权威记录在 `.state.json`。
- **加载兼容（必改项，已核实）**：`loadConfigLayer` 的枚举过滤为 `name.endsWith(".json")`、mod_id 来自 JSON 内容而非文件名——`.applied.json` 若放入 user/ **会被当作真实 user 配置解析**（mod_id 缺省为空串）。实现必须把该过滤改为 `name.endsWith(".json") && !name.startsWith(".")`（一行改动，`ModCompatManager.loadConfigLayer` 内）；`backup/` 在 user 目录之外，天然不影响加载。

## 5. 文件 Schema

### 5.1 远端清单 `{baseUrl}/{mcVersion}/{loader}/manifest.json`

```json
{
  "schemaVersion": 1,
  "name": "ControlFlex Community Configs",
  "generated": "2026-08-15T00:00:00Z",
  "items": [
    {
      "mod_id": "jei",
      "mod_name": "Just Enough Items",
      "home_pages": [
        { "name": "CurseForge", "url": "https://www.curseforge.com/minecraft/mc-mods/jei", "description": "项目主页" },
        "https://modrinth.com/mod/jei"
      ],
      "path": "mods/jei.json",
      "sha256": "e3b0c442...",
      "description": "JEI 手柄适配",
      "dependencies": [
        { "mod_id": "cfx-jei-extra", "mod_name": "JEI 扩展", "home_pages": ["https://..."], "description": "可选" }
      ]
    }
  ]
}
```

- `mod_id`：清单内唯一，小写字母数字、下划线与连字符（正则 `[a-z0-9_-]+`）。
- `home_pages`：可选，元素两种形式任选：完整对象 `{name, url, description}`（`url` 必填且为合法 http(s) URL）或纯 URL 字符串；可混用，内存中归一化为对象形式。
- `path`：相对清单所在目录（约定 `mods/<文件名>.json`），仅用于拼下载 URL。
- `sha256`：内容哈希，变体身份、去重键、完整性校验的唯一依据（64 hex）。
- `dependencies`：仅元数据展示，客户端不解析依赖关系、不做安装联动。
- `schemaVersion`：更高主版本 → 提示"请升级应用"，不尝试解析，该源视为失败；`generated`：展示配置更新时间。
- mod_id 跨源撞名（且 sha256 不同）= 同一 mod 的变体，按 sha256 归并——社区自行协调命名，客户端不做归属仲裁。

### 5.2 源列表 `repo/sources.json`

```json
{
  "schemaVersion": 1,
  "sources": [
    { "baseUrl": "https://cdn.jsdelivr.net/gh/ControlFlexMC/cfx-compat-configs@main", "enabled": true, "builtin": true },
    { "baseUrl": "https://raw.githubusercontent.com/ControlFlexMC/cfx-compat-configs/refs/heads/main", "enabled": true, "builtin": true }
  ]
}
```

- 有序数组，顺序决定元数据归属与 URL 尝试顺序（照搬原方案）；`enabled=false` 的源不参与同步与并集。
- 首次运行播种两个内置源；加载时非法条目（非 http(s)、无 host）忽略并记 warning，不影响其余源；文件损坏整体回退默认双源（记日志）。
- 「恢复默认源」：重新启用两个内置源、恢复默认顺序（CDN 在前），用户自添源保留其后。

**源 id 推导**（照搬）：全部转小写后——

1. host 为 `cdn.jsdelivr.net` 且 path[0] 为 `gh` → `${path[1]}@${host}`；
2. 有 path 段 → `${path[0]}@${host}`；
3. 无 path 段 → `${host}`；
4. 仍冲突 → 按列表顺序加后缀 `-1`、`-2`。

| baseUrl | 源 id |
| --- | --- |
| `https://cdn.jsdelivr.net/gh/ControlFlexMC/cfx-compat-configs@main` | `controlflexmc@cdn.jsdelivr.net` |
| `https://raw.githubusercontent.com/ControlFlexMC/cfx-compat-configs/refs/heads/main` | `controlflexmc@raw.githubusercontent.com` |

- 删除源 = 从数组移除该条目；其 `repo/manifest/<源id>/` 按 `.state.json` 中 baseUrl 匹配后删除；content 因跨源共享不随删源清理，归手动 gc。

### 5.3 每源状态 `repo/manifest/<源id>/.state.json`

```json
{
  "schemaVersion": 1,
  "baseUrl": "https://cdn.jsdelivr.net/gh/ControlFlexMC/cfx-compat-configs@main",
  "mcVersion": "1.20.1",
  "loader": "forge",
  "lastSyncAt": "2026-08-15T10:00:00Z",
  "manifestSha256": "ab12cd34..."
}
```

- `mcVersion`/`loader`：本次同步实际使用的目录段。内容 URL 拼接**必须用这里记录的值**而非当前代码重新检测——防止未来版本检测变化后的混合期 404。
- `manifestSha256`：清单副本的 sha256（字节严格对应），用于快速判断清单是否变化；远端 404（该源无当前版本目录）时无此字段/为 null。
- 单分类模型（仅当前加载器），无 repo-config.md 的 `manifests` 分类映射与 `layoutVersion`。

### 5.4 应用追踪 `user/.applied.json`

```json
{ "schemaVersion": 1, "applied": { "jei": "e3b0c442..." } }
```

- 记录每个 mod_id 已应用的变体 sha256；apply 时原子更新（tmp+rename）。
- 展示时比对 `user/<mod_id>.json` 现场哈希：相符 → `已应用`；不符 → `已手动修改`；无记录 → `未追踪`。
- 文件损坏回退为空记录（全部显示未追踪），不影响解析/apply；记 warning。

## 6. 同步、内容获取与清理

触发：客户端初始化完成后异步静默同步（经 `Services.LIFECYCLE.onKeyMappingsReady` 一次性触发，不阻塞启动，读取先走本地；已核实该钩子在 fabric/forge 两侧均可用）；另提供手动「同步最新配置」（§8.3）。二者共用单例 `RepoSyncJob`（决策 14）。每源同一时刻仅一个同步任务（源级互斥锁），不同源可并行。

### 6.1 单源同步（syncSource）——只刷新清单，零内容下载

1. `GET {baseUrl}/{mcVersion}/{loader}/manifest.json`（连接 5s / 读取 30s；跟随 301/302，拒绝 https→http 降级；2MB 流式限量）。
2. 解析 + 校验（schemaVersion、mod_id 唯一性与合法性、path 安全性、sha256 格式）。
3. 原子写 `manifest.json`（逐字节副本）→ 原子写 `.state.json`（含本次使用的 mcVersion/loader 与清单哈希）。
4. 404 → info 级"该源无当前版本清单"（不算失败），保留旧副本；网络失败/解析失败/超限 → 该源失败（记入 job 失败列表），旧副本保留继续参与并集。

> CDN 缓存事实（沿用原方案已核实结论）：jsDelivr 对 `@main` 分支引用缓存约 12 小时、raw.githubusercontent 约 5 分钟——清单与子文件可能来自不同缓存节点导致版本不一致；本方案靠「下载文件哈希与清单不符 → 该 URL 失败 → 换镜像 URL」的 failover 天然吸收（双官方源互为镜像）。

### 6.2 内容获取（ensureContent(modId, sha256, urls)）——预览/apply 时懒加载

1. `content/<modId>/<sha256>.json` 存在 → 哈希复核：相符直接返回；不符（篡改/损坏）删除坏文件继续。
2. 按 urls 顺序（源列表序；URL = `{baseUrl}/{state.mcVersion}/{state.loader}/{path}`，由 CatalogIndex 构建时生成并去重）逐个：下载（2MB 流式上限）→ 校验 sha256 → 首个成功者原子写盘（tmp 名含唯一随机段 + rename，并发下载同一变体互不干扰）返回。
3. 单 URL 失败立即换下一个；超限（TooLarge）的 URL 本轮剔除（确定性错误）。
4. 整轮全败 → 指数退避后重试整轮，最多 2 轮；仍败则报错，本地不受影响。

### 6.3 手动清理（gc）——仅 API，本轮无 UI

- 孤儿判定：content 中 `(mod_id, sha256)` 不被任何启用源当前清单副本引用；manifest 区中 `.state.json` 的 baseUrl 不在当前源列表的目录同为孤儿。
- `gc()` 先返回孤儿清单供确认，确认后删除；顺带清理残留 `*.tmp`（跳过 mtime 一分钟内的新鲜 tmp）。
- 同步流程永不自动删除 content。

### 6.4 RepoSyncJob（单例）

- 状态机 `IDLE/RUNNING/FINISHED/FAILED/CANCELLED`；进度字段 `(doneSources, totalSources, currentSource, currentStage)` 与失败列表；UI 每 tick 轮询读取。
- 协作式取消：置 cancelled 标志，各下载点检查后提前退出（仿 `ModJarScanner`）。
- 源列表变更（新增/重新启用源）→ 保存后触发新 job（静默，不弹进度窗）；此时若有 job 在跑，则排队等其结束后执行（保持单例 job 模型，进度展示与取消语义简单）。

## 7. 浏览、选择与应用

### 7.1 并集索引（RepoCatalogIndex）

内存构建（启动/同步后/源列表变更后），从全部**启用**源的清单副本合并：

```
mod_id -> {
  sha256 -> {
    urls[按源顺序],
    modName/homePages/description/dependencies[首个提供源的],
    providers[源id...]
  }
}
```

- 某源清单副本缺失/损坏 → 跳过该源（记 warning），不影响并集其余部分。
- 索引构建时生成每个变体的完整 URL 列表（用各源 `.state.json` 的 mcVersion/loader 拼接）并去重。
- 重建时在后台线程构建新实例、完成后原子替换引用（volatile 单引用）；读取端永远拿到一致快照。

### 7.2 查询

- `countVariants(modId)` → 变体数（列表页徽章、详情页横幅用）。
- `listVariants(modId)` → 变体列表，每项含 sha256、元数据、providers、`downloaded`（content 存在）、`applied`/`modified`/`untracked` 三态标注；排序确定性：providers 首个源在源列表中的位置升序 → 同位置按 sha256 字典序。

### 7.3 应用（apply(modId, sha256)）

1. `ensureContent`（懒加载 + 镜像 failover）。
2. `user/<modId>.json` 不存在 → 直接原子 copy 内容文件；存在且现场哈希与内容哈希**相同** → 跳过 copy（幂等，不产生备份）；存在且**不同** → 旧文件先 copy 到 `backup/<modId>-<yyyyMMdd-HHmmss>.json`（目标名碰撞则追加 `-1`、`-2`），再原子覆盖 `user/<modId>.json`。
3. 原子更新 `user/.applied.json`。
4. `ModCompatManager.reloadUserConfig(modId)` 生效。

任一步失败：user 与 backup 均不动（备份先于覆盖，覆盖失败时多出的备份文件无害），报错返回。

## 9. 错误处理

| 场景 | 处理 |
| --- | --- |
| 某源清单失败（网络/解析/超限） | 该源记入 job 失败列表（记 warning），旧副本继续参与并集，旧目录仍可浏览可 apply |
| 源无当前 mcVersion/loader 目录（404） | info 级"该源无当前版本清单"，不算失败；旧副本保留 |
| ensureContent 全 URL 失败 | 预览页显示错误 + 重试；apply 报错；user 层与 content 现有文件不受影响 |
| 响应超过 2MB | 流式检测即刻丢弃（确定性错误不重试）；清单超限走清单失败路径，内容超限剔除该 URL |
| content 文件被篡改/损坏 | 使用前哈希复核发现 → 删坏文件 → ensureContent 重下自愈 |
| 下载中途被杀 | 校验后才写 tmp；rename 原子——正式文件永不半写；残留 tmp 由手动 gc 清理（tmp 名含唯一随机段，互不覆盖） |
| `.applied.json` 损坏 | 回退空记录（记 warning），不影响解析/apply |
| `sources.json` 损坏 | 整体回退默认双源（记日志）；非法条目过滤不影响其余源 |
| 磁盘写入失败 | 中止当次操作；所有写入均 tmp+rename，现有文件不受影响 |

> **不变量**：任何失败都不会让本地缓存比失败前更坏——要么完整替换成功，要么保持原样。
> **可观测性**：所有静默降级路径经 `ControlFlexLogger` 输出 WARNING，行为不变、只增可见性。

## 10. 测试策略

- **单元测试**：清单解析/校验（坏 JSON、未知 schemaVersion、路径穿越 payload、非法 mod_id/sha256、home_pages 对象/字符串/混用形式与非法 url、dependencies 数组与单对象兼容）；源 id 推导（默认规则/jsDelivr 特例/小写化/无 path/冲突后缀）；sources.json 损坏回退/非法条目/恢复默认源/内置源删除拒绝；CatalogIndex（并集、同 sha256 去重与 URL 合并、元数据首源胜出、providers、坏副本跳过、禁用源排除）；applied 追踪（三态、损坏回退）；备份命名与碰撞（`-1`/`-2` 后缀）；apply 四分支（不存在/相同/不同+备份/失败不动）。
- **集成测试**（本地 `com.sun.net.httpserver` 桩）：同步只拉当前加载器清单零内容请求、404=info 不失败且保留旧副本、源网络失败隔离、ensureContent 多 URL failover（首挂→次成、全挂整轮重试、超限剔除）、并发 apply 同一变体安全（唯一 tmp 名）、content 篡改自愈、重复同步幂等（清单不变时哈希与副本字节均不变）、job 协作式取消、URL 拼接使用 `.state.json` 的 mcVersion/loader。
- **端到端验收**（mc-cfx MCP + 本地桩服务器或系统属性重定向的官方源）：完整链路——启动自动同步 → 列表页徽章 → 详情页横幅 → 变体列表（三态标注）→ 预览页（下载进度/失败重试）→ Apply → backup 时间戳文件生成 → user 文件生效（`[ControlFlex/]` 日志 / 行为变化）→ 再次 Apply 不同变体 → 二次备份；「编辑源列表」添加桩源/禁用内置源/排序/恢复默认；「同步最新配置」停止更新与后台运行（attach 不重启）；离线启动（缓存可浏览可 apply）。
- **故障注入**：服务器宕机/字节损坏/重定向开关；`.applied.json`/`sources.json` 写坏验证回退；预置 `*.tmp` 残留验证 gc 清理。
