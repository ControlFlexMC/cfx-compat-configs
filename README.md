# cfx-compat-configs

[中文](./README_ZH.md)

Community **mod compatibility configs** for [ControlFlex](https://www.curseforge.com/minecraft/mc-mods/control-flex) (CFX): JSON files that tell the mod how to handle third-party key bindings, dispatch channels, cross-phase keys, and stick/cursor behavior in screens & overlays.

> **⚠ Version requirement:** The configs on this branch (`0.8.7`) target **ControlFlex ≥ 0.8.7** and use the current config format (`mod_versions` + `inGameKeys`/`screenKeys`/`overlayKeys` channels model).
> ControlFlex pins its built-in source URLs to the **matching branch** of this repository per release, so in-game sync always serves configs compatible with your installed version. Legacy-format branches: [`0.8.5`](https://github.com/ControlFlexMC/cfx-compat-configs/tree/0.8.5) · [`0.8.4`](https://github.com/ControlFlexMC/cfx-compat-configs/tree/0.8.4).

---

## How it works

**Players** don't need to touch this repository: ControlFlex ships it as a built-in config source. Open **Settings → Mod Adaptation → More → Sync latest configs** (a silent sync also runs after startup), then on a mod's detail page follow the community-configs banner → preview → **Apply** — it writes `user/<mod_id>.json`, takes effect immediately, no restart. Undo with "Reset config" or by deleting the file (falls back to built-in defaults).

Manual install also works: copy a config from [`<mc-version>/<loader>/mods/`](./1.20.1/forge/mods/) into `config/controlflex/compat/user/<mod_id>.json` and restart. ControlFlex loads compat configs from three layers, priority `user` > `mods` > `default`:

- `default/` — built-in configs shipped with ControlFlex (extracted from the JAR, never overwritten)
- `mods/` — installed by bridge mods (`cfx-compat-*` / plugin mods)
- **`user/`** — your configs (highest priority; also where Apply writes)

Legacy `{modid}_keys.json` files in the old format are auto-migrated on startup.

## Repository layout

```text
<repo-root>/
├── 1.20.1/                  # MC version (exactly as SharedConstants reports it)
│   ├── forge/
│   │   ├── manifest.json    # generated index of the configs below
│   │   └── mods/
│   │       ├── epicfight.json
│   │       ├── irons_spellbooks.json
│   │       └── ...
│   └── fabric/
│       ├── manifest.json
│       └── mods/
├── 1.21.1/
│   ├── neoforge/
│   └── fabric/
└── ...
```

The client fetches `{baseUrl}/{mcVersion}/{loader}/manifest.json`, then downloads individual configs on demand and verifies their `sha256`. The manifest is (re)generated by [`generate_manifest.py`](./generate_manifest.py).

## Config format at a glance

Each file (`mods/<mod_id>.json`) declares `mod_versions` rule sets evaluated **first-match-wins**. A rule set declares keys per context — `inGameKeys` / `screenKeys` / `overlayKeys` — each with **dispatch channels** (`keyMapping`, `eventBus`, `glfwPoll`, `screenInput`, `virtualKbm`), plus extras: `phasePersistentKeys`, `ignoreKeys`, `itemSuppressKeys`, `tips`, and per-screen/overlay stick & cursor behavior.

Minimal template (see the [field reference](./docs/01.config-field-reference.md) for every field):

```json
{
  "mod_id": "examplemod",
  "contributors": ["yourname"],
  "config_version": "1.0.0",
  "mod_versions": [
    { "version": "", "inGameKeys": {}, "screenKeys": {}, "overlayKeys": {},
      "ignoreKeys": [], "tips": [], "screen": {}, "overlay": {} }
  ]
}
```

## Contributing

1. **Fork** this repository and switch to the branch matching your target ControlFlex version (e.g. `0.8.7`).
2. **Create** `<mc-version>/<loader>/mods/<mod_id>.json` (bare key names from the mod's Controls category; find them in-game or via `[ModCompat]` log lines) and copy it to every loader directory it applies to.
3. **Regenerate manifests**: `python3 generate_manifest.py` — commit the updated `manifest.json` files too.
4. **Test in-game** (add your fork as a [source](./docs/02.build-your-own-compat-source.md#9-local-testing) or copy to `user/`), then **open a pull request** with: mod name & version tested, loader(s), and what the config fixes.

You can also skip the PR and run your own source — see [doc 02](./docs/02.build-your-own-compat-source.md).
